# AI Traffic Optimization (complete project)

This is a starter pack for adding the five requested features to your existing Python + YOLO/OpenCV project.

## What is included

1. `train_custom_yolo.py` — fine-tunes YOLOv8 on your own labeled vehicle dataset.
2. `dataset/data.yaml.example` — example dataset configuration.
3. `make_demo_history.py` — creates clearly synthetic example history so you can test the prediction pipeline.
4. `predict_congestion.py` — predicts a lane's vehicle count 15 minutes ahead from historical counts.
5. `signal_timing_demo.py` — safely compares fixed vs adaptive signal timing in a toy queue simulation.
6. `sumo/README_SUMO.md` — setup steps and the official SUMO TraCI tutorial for a more realistic simulation.
7. `simulated_signal_controller.py` — a software-only signal controller example. It does not connect to real traffic lights.

## Important

- Training a custom model requires labeled images. A video alone is not a labeled training dataset.
- The synthetic history generated by `make_demo_history.py` is only for testing code; do not present it as real traffic data or as proof of improved prediction accuracy.
- The toy signal timing comparison is an educational simulation, not a validated traffic-engineering result.
- Do not connect this project to public-road traffic signals. Use SUMO or a low-voltage classroom demo with adult/supervisor guidance.

## Install

From your project folder in PowerShell:

```powershell
python -m pip install -r requirements.txt
```

`pip install eclipse-sumo traci` installs SUMO itself, so no separate installer is needed.

## Run order

0. `python extract_frames.py --source traffic.mp4` : saves frames, resizes, denoises, normalizes (guide step 2).

1. `python traffic_counter.py --source traffic.mp4` : detect, count, show density and green time. Also writes `traffic_history.csv` (use `--interval 60` for short videos, `--no-show` for no window, `--save output.mp4` to record).
2. `python predict_congestion.py --data traffic_history.csv ` : needs 30+ rows (real counts).
3. `python signal_timing_demo.py` : toy fixed vs adaptive.
3a. `python label_density.py` : look at saved frames and press 1/2/3 (LOW/MEDIUM/HIGH); about 50 labels is enough.
3b. `python train_density_classifier.py --data density_samples.csv` : LOW/MEDIUM/HIGH classifier. `traffic_counter.py` writes `density_samples.csv`; fill its `label` column by hand for real accuracy (otherwise weak rule labels are used and the score means nothing).
3c. `python train_density_tf.py` : same classifier in TensorFlow/Keras.
3d. `python make_yolo_dataset.py --source traffic.mp4` then `python train_custom_yolo.py --data dataset/data.yaml` : fine-tune YOLO on your own video (auto-labeled; or put the Kaggle dataset in `dataset/` instead).
4. `python sumo/run_sumo.py --seeds 5` : now also reports average/max queue length and CO2. SUMO fixed vs adaptive on a 4-way junction (network and demand files included).

## 1) Custom YOLO model

1. Prepare a YOLO-format dataset with labeled images, split into `train` and `val`.
2. Copy `dataset/data.yaml.example` to `dataset/data.yaml`.
3. Edit the paths in `dataset/data.yaml` to match your dataset.
4. Run:

```powershell
python train_custom_yolo.py --data dataset/data.yaml --epochs 30
```

The resulting weights will be under `runs/detect/vehicle_custom/weights/best.pt` (or the next incremented run folder).

Then test it in your existing project:

```powershell
python traffic_counter.py --source traffic.mp4 --weights runs/detect/vehicle_custom/weights/best.pt
```

## 2) Congestion prediction

For a quick pipeline test:

```powershell
python make_demo_history.py
python predict_congestion.py --data traffic_history_demo.csv 
```

The demo CSV is synthetic. For a meaningful model, log actual counts at fixed intervals from your camera/video and save them with columns:

`timestamp,lane,vehicle_count`

Use several days or weeks of consistent observations if possible. A model trained on synthetic demo data is not a real-world forecast.

## 3) Fixed vs adaptive signal timing demo

```powershell
python signal_timing_demo.py
```

It prints average waiting time from a simplified simulation. Results vary with the random seed and are only a demonstration of how to compare approaches fairly.

## 4) SUMO

`sumo/` now has a ready 4-way network (`net.net.xml`, built from `nodes.nod.xml` + `edges.edg.xml`), demand generator (`gen_routes.py`) and `run_sumo.py`, which runs fixed-time vs queue-based adaptive control through TraCI and prints mean waiting and travel time per seed. See `sumo/README_SUMO.md` for the official tutorials.

## 5) Signal controller

`simulated_signal_controller.py` contains a safe software-only decision function. It gives bounded recommendations and includes a minimum green, maximum green, and yellow/all-red clearance concept. It is not certified for real-world deployment.


## About the sample video
`traffic.mp4` is filmed from a moving vehicle (Bangkok street). Lane boxes `Left` and `Right` in `traffic_counter.py` cover the road ahead. Use **vehicles in the ROI** (density) as the main measure; "vehicles crossed the line" is unreliable because the camera itself moves. For a fixed junction camera both are valid. Edit `LANES` for any other video.
